# System Design: Reflective Markdown Journaling System

## 1. Core Philosophy & Constraints
This system is designed as a **quiet, reflective digital sanctuary**. It is an instrument for self-awareness, not a content consumption platform or a clinical tool.

**Primary Constraints:**
* **Source of Truth**: The Markdown file is the database. Nothing exists outside of it.
* **Agency**: The user owns the data. The system observes and assists but never overrides.
* **Safety**: No clinical claims. No emotional manipulation. AI is a "ghost in the machine"—silent unless summoned, and always optional.

## 2. Architecture & Stack

### Technology Stack
* **Framework**: Next.js (React) - chosen for robust static generation and component architecture.
* **Content Engine**: MDX (Markdown + JSX) - allows embedding rich components (Spotify player) while keeping text portable.
* **Styling**: Tailwind CSS - for a utility-first, custom design system without rigid framework constraints.
* **State Management**: Local React state (minimal global state needed).
* **Storage**: Local File System (Git-backed).

### Build Pipeline
1.  **Ingest**: System reads `.mdx` files from a `content/journal` directory.
2.  **Parse**: `gray-matter` or similar extracts YAML frontmatter (metadata) and body.
3.  **Transform**: Markdown body is compiled to React components. Custom schemas (e.g., `::spotify[...]`) are transformed into safe Embed components.
4.  **Enrich (Optional)**: If enabled, an LLM pipeline analyzes the text *at build/edit time* to suggest reflection prompts, which are then written back to the file's metadata (user approves).

## 3. Data Model (Markdown Schema)

The specific structure of a journal entry.

### Frontmatter (YAML)
```yaml
---
id: "2023-10-27-evening-reflection"
date: "2023-10-27T19:30:00Z"
tags: ["anxiety", "hope", "evening"]
mood: "contemplative"
music:
  track_uri: "spotify:track:123456789"
  context: "grounding" # User's intent for choosing this song
reflection_prompts: # Generated by system, stored here. Rendered optionally.
  - "What physical sensation accompanies this feeling of hope?"
---
```

### Body Content
Standard Markdown for writing.

## 4. UX & Interface Design

### Visual Language
*   **Typography**: Serif for body text (e.g., Merriweather, EB Garamond) to evoke a book-like feel. Sans-serif for UI (Inter) to remain neutral.
*   **Whitespace**: Generous margins. Text centered, max-width ~65ch (optimal reading length).
*   **Color**: "Paper" themes—warm off-whites, dark charcoal text. Dark mode is a deep slate/ink, not absolute black.
*   **Noise Reduction**: Minimal UI chrome. No sticky headers. Controls fade out when typing.

### Component: The "Quiet" Spotify Embed
*   **Visuals**: Small, monochrome or desaturated album art until hovered.
*   **Behavior**: distinct "Play" intention required. No autoplay.
*   **Caption**: Displayed near the player: *"Chosen for keeping me grounded during the storm."*

### Component: Reflection Prompts
*   **State**: Collapsed by default. A subtle indicator (e.g., a small "✦" icon / "Reflect") in the margin.
*   **Interaction**: specific click to reveal.
*   **Content**: "You mentioned feeling 'rushed'. Where do you feel that hurry in your body right now?"

## 5. AI Prompt System Design

**Role**: The AI is a "Bibliophile Librarian" or "Quiet Observer". It organizes and tags, and occasionally asks a thoughtful question.

**Prompt Engineering Rules:**
*   **Input**: The journal entry text.
*   **Output**: JSON array of strings (questions).
*   **Constraints**:
    *   Max 2 questions.
    *   No "Why" questions (can lead to rationalization). Use "What" or "How" (leads to sensing).
    *   Valid: "What is the texture of this anger?"
    *   Invalid: "Why are you angry?" / "You should try taking a breath."
    *   **Safety Filter**: If text contains strong indications of self-harm or severe distress, suppress all prompts. Output specific safe-resource code instead.

## 6. Implementation Stages

### Phase 1: The "Silent" Journal (MVP)
*   Next.js app setup.
*   Markdown file reading/rendering.
*   Spotify component integration (manual URI entry).
*   Basic styling.

### Phase 2: The "Listening" Journal
*   Integration of local LLM (e.g., via Ollama) or API (OpenAI/Anthropic) for *optional* prompt generation.
*   "Generate Prompt" button implementation.

### Phase 3: The "Garden"
*   Tag explorer.
*   Mood tracking visualization over time.
